# 生成器自身测试策略:清单快照 + 定点断言,运行时冒烟仅限 full,门禁维持单环境

在 ADR-0004 已定的质量门禁(每预设「生成 → `mvn compile` → 前端 `npm run build`」)之上,生成器自身的测试体系定为四层。**单测层**:问答会话(问题树装配、校验、默认值、白名单裁剪)与模板渲染逻辑必须下沉为不依赖终端的纯逻辑层,用 JUnit 5 + AssertJ 普通单测覆盖——可测性因此成为架构约束,交互 UI 只留渲染与按键转发。**生成管线集成测试层**:测试以全参数模式子进程端到端跑 CLI,断言退出码与生成物;生成物断言采用「文件清单快照 + 关键文件定点断言」混合制——每预设一份 golden 文件清单快照(捕捉多了/少了文件),内容层面对 pom 版本坐标、主类、条件渲染分叉点、权限注解、菜单 SQL 关键行做定点断言(捕捉渲染错变量);快照更新必须走显式开关(如 `-DupdateSnapshots`),快照 diff 作为 PR 一部分人工 review。**PR 门禁层**:维持单环境(ubuntu-latest × JDK 21 × 两档预设)不扩;full 预设在其上加一条 golden-path 运行时冒烟——CI 起 MySQL service container、执行初始化 SQL、启动后端、断言健康端点 200 与登录接口错误凭证 401/种子用户正确凭证 200、前端 preview 抓首页——因为「编译能过但应用起不来」(配置渲染错、初始化 SQL 错、Bean 冲突)是模板回归的高发区;empty 预设无功能包无 SQL,维持编译深度;运行时冒烟只此一条,不随任何矩阵放大。**nightly 扩展矩阵层**:ubuntu + windows × JDK 21 × 两档预设跑门禁同管线(不含运行时冒烟),定时 + 手动触发,红灯只告警不阻塞合入——windows 一维专为抓路径分隔符/换行符这类代码生成器经典故障。CLI 交互 UI 另留 1~2 条 pty4j 伪终端 golden-path 冒烟(选预设 → 默认值回车到底 → 生成成功),防「逻辑对但 UI 卡死」,这是终端路线公认痛点被控制后的最小保险。

## Considered Options

- **生成物全量内容快照(JHipster 式)**:模板高频迭代期每次变更都要批量 accept,review 流于 approve-all,格式微调(换行、缩进)制造大量噪音;清单快照 + 定点断言以低维护成本覆盖「漏文件」与「渲染错」两类回归。拒绝。
- **交互层大规模 PTY 端到端测试**:脆弱、慢、平台差异大;自研 Tab 表单已按 ADR-0001 落成 jline-terminal 原语,决策/校验逻辑全部下沉后 UI 层只剩渲染,不值得大规模 PTY。拒绝,仅留 1~2 条冒烟。
- **Web 向导(CLI 起向导跳网页操作、完成回 CLI)**:可测性(Playwright)与复杂交互表达力确实更强,但要推翻 ADR-0001 自研交互层与 ADR-0006 两段式终端向导,给生成器新增一整个前端交付面;且信创典型环境是无桌面服务器 + SSH,跳网页(端口转发、浏览器可用性)反而更差;MVP 范围显著膨胀。拒绝进 MVP,记入地图 Out of scope 归第二阶段候选。
- **国产 JDK/OS 冒烟进 CI**:与蓝图已拍板「国产 JDK/OS 适配 = 声明兼容 + 部署文档,不做实测认证」保持一致;麒麟/统信 UOS 无 GitHub Actions runner,国产 JDK ARM 无 runner。MVP 不做,项目稳定后再议(记入地图 Out of scope)。
- **测试覆盖率数字门禁**:MVP 期数字门禁只制造凑数测试。拒绝,约束改为「纯逻辑层必须有测」,由 review 把握。
- **nightly 矩阵含 macOS 维度**:与 ubuntu 同为 POSIX,相对 windows 抓不到增量故障类。拒绝。
- **生成物矩阵扩 JDK 版本**:生成器基线与目标应用均锁 JDK 21,无第二版本要验。拒绝。

## Consequences

- **施工单元(交「拍板:施工单元切分与实施计划总览成文」#24 编织进总计划)**:
  - T1 单测基建 + 逻辑下沉(CLI 骨架阶段):问答会话与渲染逻辑为纯逻辑层且有单测;单测不启动终端;`mvn test` 全绿。
  - T2 生成管线集成测试通道(CLI 骨架阶段,先 base/empty,随 full 模板化扩展):每预设至少一条全参数模式端到端生成测试;清单快照 + 定点断言落地;快照显式更新开关可用;断言失败信息能定位到具体文件。
  - T3 PR 门禁 workflow(CLI 骨架阶段立起,full 模板化完成时接入):两档预设「生成 → 编译 → 前端 build」全绿才可合入 main;失败日志可直接看出失败环节。
  - T4 full 预设运行时冒烟(full 模板化完成后):MySQL container + 初始化 SQL + 启动 + 端点断言 + 前端 preview;脚本随仓库;单次增量 ≤5 分钟。
  - T5 nightly 扩展矩阵(门禁稳定后任何时候):windows 红灯能区分路径/换行符类与真回归;告警制。
  - T6 PTY 冒烟(CLI 骨架阶段尾声):pty4j 驱动 1~2 条 golden path,CI 稳定运行(允许重试一次)。
- **测试代码归属**:生成器测试全部在生成器单模块 `src/test/`;运行时冒烟脚本放仓库 `ci/` 或 `.github/`,不进模板产物。
- ADR-0004 的门禁语义不变,本 ADR 是其在测试面的展开;「纯逻辑层」要求对 CLI 编排层与渲染管线的实现方式构成硬约束。

依据:拍板票据 <https://github.com/hhhrrr777/jfast/issues/22>(两轮 grilling:五问按推荐落定,Web 向导提议讨论后否决进 MVP)。
